# Review lessons

Recurring review findings on this repo, grouped by theme. Read before writing
code. A tight version lives in [`AGENTS.md`](../AGENTS.md); add a lesson here when
a reviewer flags the same mistake twice, in that PR. Prefer fixing it at the
source: a lint rule, check or hook beats a lesson, because a lesson only works if
it is read.

## CI and workflows

- Every workflow with a `pull_request` trigger guards each job against Dependabot: `if: ${{ github.actor != 'dependabot[bot]' && github.event.pull_request.user.login != 'dependabot[bot]' }}`. A new workflow without it lets dependabot PRs spend CI minutes. See `.github/workflows/ci.yml`.
- Pin third-party actions, and keep `push` triggers ignoring `dependabot/**`.

## Generated data

- Only `src/data/labs.json` is edited by hand, and only to the schema (`npm run validate`). `github-stats.json`, `links.json`, `previews.json` and `preview-sources.json` are generated by the sync scripts; hand-edits are silently overwritten on the next `npm run sync`. To change them, change the source (the repo, or the entry's `url`) and re-sync.

## Catalog metadata

- New catalog entries source their metadata upstream: a repo's GitHub topics and description, or a tracker sub-issue meta block (`CONVENTIONS.md`), not a hand-written one-off.
- An entry's `url` and preview must resolve. A dead link, or a GitHub avatar picked as the preview, is a finding. A `preview` override is a curated image or video URL; the card auto-detects video.

## Links and the base path

- Internal links use the Astro `base` (`import.meta.env.BASE_URL`); a bare root-relative `/path` 404s on GitHub Pages. The docs link check (`npm run lint:links`) catches broken links.

## Content accuracy

- Docs, README and UI copy claim only what the code does. When a change makes `AGENTS.md`, `CONVENTIONS.md` or a card description stale, update it in the same PR.

## PR hygiene

- The PR description matches the final diff; re-read it after every push. Add a changelog fragment (`npm run changelog`) or the `skip-changelog` label. Keep changes scoped, and keep data syncs separate from feature changes.
